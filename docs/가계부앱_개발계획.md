## Phase 1. 개발환경 구축 (Visual Studio Code 통합)

> **목표:** MacBook Air (Apple Silicon, macOS 26 Tahoe)에서 Visual Studio Code 하나로 Java/Spring + React/TypeScript 를 모두 개발/디버깅한다.
> **설치 철학:** **이미 시스템에 있는 도구는 그대로 사용**, **새로 설치할 것은 모두 프로젝트의 `tools/` 폴더에** — 시스템 오염 없는 격리 환경.
> **예상 소요:** 0.5~1일

### 1-0. 기본 전제 확인

| 항목 | 권장 값 | 확인 명령 |
|---|---|---|
| macOS | 26 Tahoe (또는 15 Sequoia) | `sw_vers -productVersion` |
| 아키텍처 | arm64 (Apple Silicon) | `uname -m` → `arm64` |
| 디스크 여유 | 최소 15GB | "이 Mac에 관하여 → 저장 공간" |
| 메모리 | 8GB 이상 권장 (16GB 쾌적) | "이 Mac에 관하여" |

> **MacBook Air 8GB 사용자 팁:** Chrome 탭 + Spring Boot + React Dev Server 동시 구동 시 스왑이 잦아질 수 있습니다. Phase 5/6 동시 개발 중에는 다른 무거운 앱(Docker Desktop, Slack 등)을 닫아두는 걸 권장합니다.

### 1-0-1. 프로젝트 폴더 구조 (`tools/` 격리 방식)

```
budget_book_codex/
├── tools/                              ← 프로젝트 전용 도구 (gitignore)
│   ├── jdk-21/                         JDK 21 LTS (Temurin)
│   │   └── Contents/Home/bin/java
│   ├── node-24/                        Node.js 24 LTS
│   │   └── bin/{node,npm,npx}
│   ├── Visual Studio Code.app/         (.app 번들 — 시스템 미설치 시)
│   └── DBeaver.app/                    (선택)
├── activate-env.sh                     ← source 로 환경 활성화
├── check-dev-env.sh                    ← 점검
├── install-dev-env.sh                  ← tools/ 에 자동 설치
├── backend/                            (Phase 2 에서 생성)
└── frontend/                           (Phase 2 에서 생성)
```

핵심 명령 3개로 끝:

```bash
bash install-dev-env.sh        # 누락분만 tools/ 에 설치
source activate-env.sh          # PATH/JAVA_HOME 활성화
bash check-dev-env.sh           # 점검
```

### 1-0-2. tools/ 격리 방식의 장점

1. **다른 프로젝트와 버전 충돌 없음** — 시스템 Java 17이 있어도 이 프로젝트는 Java 21 사용
2. **재현 가능** — 신규 멤버도 install 스크립트 한 번이면 동일 환경
3. **삭제 쉬움** — 프로젝트 폴더만 지우면 깨끗이 제거
4. **시스템 오염 없음** — Homebrew/시스템 PATH 건드리지 않음

### 1-1. 자동 설치 (가장 빠른 길)

스크립트가 모든 다운로드/검증을 자동 처리합니다:

```bash
cd ~/claude/budget_book_codex
bash install-dev-env.sh
```

스크립트가 수행하는 작업:
- **Git**: 시스템에 이미 있으면 그대로 사용 (없으면 `xcode-select --install` 안내)
- **JDK 21 (Temurin)**: 시스템에 21이 없으면 Adoptium 공식 tar.gz 다운로드 → `tools/jdk-21/`
- **Node.js 24 LTS**: 시스템에 24+ 가 없으면 nodejs.org 공식 tar.gz 다운로드 → `tools/node-24/`
- **Visual Studio Code**: `/Applications/`에 없으면 공식 zip 다운로드 → `tools/Visual Studio Code.app/`
- **Visual Studio Code 확장 12종**: 사용자 기본 위치(`~/.vscode/extensions/`)에 설치
- **(선택) DBeaver**: `tools/DBeaver.app/`

설치 후 활성화:
```bash
source activate-env.sh
```

이 한 줄이 현재 셸에 `JAVA_HOME`, `PATH`를 세팅해 `tools/` 안의 도구가 우선 사용되게 만듭니다.

### 1-2. 수동 설치 (스크립트를 안 쓰는 경우)

자동 스크립트가 어려운 환경이라면 아래 순서로 수동 설치할 수도 있습니다.

#### 1-2-1. Java 21 LTS — Adoptium Temurin

```bash
mkdir -p tools
curl -fSL -o /tmp/temurin21.tar.gz \
  "https://api.adoptium.net/v3/binary/latest/21/ga/mac/aarch64/jdk/hotspot/normal/eclipse"
mkdir -p tools/jdk-21
tar -xzf /tmp/temurin21.tar.gz -C tools/jdk-21 --strip-components=1
tools/jdk-21/Contents/Home/bin/java -version
```

#### 1-2-2. Node.js 24 LTS

```bash
NODE_VER=$(curl -s https://nodejs.org/download/release/latest-v24.x/ \
  | grep -o 'node-v24\.[0-9]*\.[0-9]*' | head -1 | sed 's/node-//')
curl -fSL -o /tmp/node.tar.gz \
  "https://nodejs.org/dist/${NODE_VER}/node-${NODE_VER}-darwin-arm64.tar.gz"
mkdir -p tools/node-24
tar -xzf /tmp/node.tar.gz -C tools/node-24 --strip-components=1
tools/node-24/bin/node -v
```

#### 1-2-3. Visual Studio Code

```bash
curl -fSL -o /tmp/vscode.zip \
  "https://update.code.visualstudio.com/latest/darwin-arm64/stable"
unzip -q /tmp/vscode.zip -d tools/
xattr -dr com.apple.quarantine "tools/Visual Studio Code.app"
open "tools/Visual Studio Code.app"
```

> **Gradle은 별도 설치 불필요** — Spring Initializr가 생성하는 프로젝트의 `gradlew` (Gradle Wrapper)가 알아서 다운로드합니다.

### 1-3. activate-env.sh — 환경 활성화 한 줄

새 터미널을 열 때마다 프로젝트 폴더에서 실행:

```bash
source activate-env.sh
```

스크립트가 자동으로:
- `JAVA_HOME=tools/jdk-21/Contents/Home`
- `PATH=tools/jdk-21/Contents/Home/bin:tools/node-24/bin:tools/Visual Studio Code.app/Contents/Resources/app/bin:$PATH`

> **자동화 팁:** `~/.zshrc` 끝에 다음을 추가하면 프로젝트 폴더에 들어갈 때마다 자동 활성화:
> ```bash
> cd_budget_codex() { cd ~/claude/budget_book_codex && source activate-env.sh; }
> alias bb='cd_budget'
> ```
> 이후 터미널에서 `bb` 만 치면 진입+활성화 끝.

## Phase 7. SMS 파싱 기능 개발

> **목표:** 카드 SMS 텍스트 → 거래 자동 등록.
> **예상 소요:** 3~5일

### 7-1. 흐름

```
[SMS 페이지]  ─POST /api/sms/parse(text)─>  [SmsParserService]
                                                  │ 카드사 정규식 매칭
                                                  ▼
                                          ParsedResult[]
                                                  │ 가맹점 → 카테고리 추천
                                                  ▼
[프론트 미리보기 + 체크박스]
        │
        └─ 체크된 항목  ─POST /api/transactions/batch─> 저장
```

### 7-2. ParsedResult

```java
public record ParsedResult(
    Long amount,
    String cardName,
    String storeName,
    LocalDateTime occurredAt,
    Integer installmentMonths,
    Long suggestedCategoryId,
    String raw
) {}
```

### 7-3. 카드사 정규식 — DB로 관리

`SmsParserRule` 테이블에 카드사별 패턴 저장 → 운영 중 패턴 추가/수정 시 재배포 불필요.

기본 입력 카드사: KB국민, 신한, 삼성, 현대, 롯데, 우리, 하나, BC, NH농협, 카카오뱅크, 토스뱅크, 케이뱅크.

샘플 패턴 예시:
```
[Web발신] KB국민카드(1234) 12,300원 일시불 12/05 14:23 스타벅스
[Web발신] 신한카드 승인 홍길동 5,500원(일시불) 05/17 12:34 GS25
```

### 7-4. 가맹점 → 카테고리 자동 매핑

- `MerchantRule` 사전 시드: "스타벅스/이디야/투썸 → 카페/간식", "지하철/택시/티머니 → 교통" 등 100여 개
- 사용자가 거래 저장 시 "다음부터 ___ 가맹점은 ___ 카테고리로" 옵션 → 학습

### 7-5. 다중 SMS 일괄 처리

여러 줄 붙여넣기 → 각 라인을 분리 → 미리보기 리스트(체크박스) → 일괄 저장.

### 7-6. 테스트

- 카드사별 샘플 10건씩 JUnit 단위 테스트
- 새 패턴 발견 시 테스트 케이스 추가 후 정규식 수정

## Phase 9. 테스트 및 배포

> **목표:** 실서버에서 어디서나 사용 가능.
> **예상 소요:** 1~2주

### 9-1. 테스트

| 종류 | 도구 | 내용 |
|---|---|---|
| 백엔드 단위 | JUnit 5 + Mockito | Service, Parser |
| 백엔드 통합 | `@SpringBootTest` + Testcontainers | Controller~Repository 전 구간 |
| 프론트 단위 | Vitest + RTL | 컴포넌트, 훅 |
| E2E | Playwright | 핵심 시나리오 |

### 9-2. 빌드

```bash
# 프론트
cd frontend && npm run build      # dist/

# 프론트 산출물을 백엔드 정적 리소스로 복사
mkdir -p ../backend/src/main/resources/static
cp -r dist/* ../backend/src/main/resources/static/

# 백엔드 통합 빌드
cd ../backend && ./gradlew clean bootJar
# build/libs/backend-0.0.1.jar 단일 파일 완성
```

### 9-3. 운영 DB 전환

`application-prod.yml`
```yaml
spring:
  datasource:
    url: jdbc:mysql://${DB_HOST}:3306/mybudget?serverTimezone=Asia/Seoul&useSSL=true
    username: ${DB_USER}
    password: ${DB_PASS}
  jpa:
    hibernate:
      ddl-auto: validate
  flyway:
    enabled: true
```

- **Flyway**로 마이그레이션 버전 관리

### 9-4. 배포 옵션 (입문자 친화 순)

| 옵션 | 설명 | 비용 |
|---|---|---|
| **Railway** | Git push → 자동 배포, MySQL 부가 | 무료 티어 → $5~ |
| **Render** | 비슷한 PaaS, 무료 슬립 있음 | 무료 → $7~ |
| **Fly.io** | Docker 기반, 글로벌 | 무료 한도 후 사용량 |
| **AWS Lightsail** | 가상서버에 JAR + Nginx + MySQL | 월 $5~10 |
| **자가서버 (NAS/홈서버)** | 가정용 라우터 + 도메인 + Let's Encrypt | 전기/유지비 |

### 9-5. 도메인 + HTTPS

- 가비아·후이즈에서 도메인 구입
- Cloudflare 무료 SSL 또는 Let's Encrypt(`certbot`)

### 9-6. 모니터링

- Spring Boot Actuator `/actuator/health`
- Sentry (프론트·백 모두) — 에러 자동 수집
- 로그 로테이션 + 백업
